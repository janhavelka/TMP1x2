# TMP1x2 cross-library audit, 2026-09-26

The audit found a temperature-format correctness defect, CLI lifecycle and
parsing defects, and build/package consistency gaps. The confirmed defects were
fixed with regression coverage. A follow-up implementation closes the identified
owner-operation, diagnostic CLI and model/address gaps. TMP1x2 follows applicable
sibling-library conventions while preserving the sensor's protocol differences.

## Scope and comparison basis

Reviewed TMP1x2 public headers, implementation, shared CLI, Arduino and native
IDF adapters, tests, build files, version generation, documentation and package
contents. Three parallel reviews covered core/health, CLI/adapters and repository
integration, followed by independent review of the core changes.

The sibling inventory included all 16 standalone I2C libraries: **24Cxx,
ADS1115, BME280, INA228, INA3221, LDC1614, LSM6DS3TR, MB85RC, MCP45HVX1,
OPT4001, PCA9555, RV3032-C7, SCD41, SHT3x-main, SSD1315 and TCA9548A**.
`EEPROM_24Cxx` was empty. Applications, SPI/UART/single-wire libraries, downloaded
dependencies and archived copies were excluded. Broad inventory/header checks
were combined with deeper comparison against ADS1115/OPT4001 for sensor APIs,
SHT3x/OPT4001/24Cxx for CLI behavior and BME280/24Cxx for native IDF integration.
This was a TMP1x2 audit, not an exhaustive correctness audit of each peer.

Protocol checks used the archived TI datasheets and reference sources. All
archive entries matched the existing SHA-256 manifest; no vendor artifact was
modified. [Comparison inventory](library-comparison.md).

## Confirmed findings and fixes

| Priority | Before / reproducible trigger | Fix and regression evidence |
| --- | --- | --- |
| High | Observe an external EM format change, then adopt that format with a setter. CONFIG could match while TEMP still contained the old payload; the device model reproduced **25 C reported as 50 C** with an OK result. Restoring CONFIG before recovery could similarly lose evidence. | Preserve a pending format refresh after observing differing CONFIG or TEMP markers. Matching readback or a new desired setting cannot clear it. Recovery obtains a completed conversion. Tests cover every managed CONFIG observer, TEMP observations, adoption/restoration, invalid TEMP bits, missing clock, end/rebind and begin. |
| High | CONFIG read proves a format change, but a later threshold read or recovery read fails. The earlier observation was discarded, allowing a later setter to trust the stale payload. | Record format evidence immediately, before another transfer or precondition failure. Failed output arguments stay unchanged. Fault injection covers both threshold reads and recovery's second CONFIG read. |
| Medium | `unbind; shutdown; begin`, or a rejected setter while ended, copied the core's empty/default configuration back into the CLI, losing callbacks or the selected target. | Synchronize normalized configuration only from a valid binding/initialized managed operation. Regression exercises rejected shutdown, threshold and rate commands and subsequent begin. |
| Medium | `end; addr 0x49; recover` displayed 0x49 while recovering the previous 0x48 binding. | Ended address/model changes update the binding without I2C. Probe/recovery use the selected address; tests assert actual callback addresses. |
| Medium | `stop`, or the watch's completion timeout, left automatic core polling active on every idle CLI tick. | Only active watches issue background transfers. Stop/timeout is bus-silent afterward. A pending conversion can be consumed explicitly or joined by another watch. |
| Medium | A transient shutdown-watch read failure cleared the CLI's pending flag while the core retained the conversion; following attempts failed BUSY. | Track the core's pending state and join it on subsequent attempts. Tests inject a read error and verify successful resumption without another trigger. |
| Medium | Tabs were discarded, merging command tokens. Other discarded control bytes could turn malformed `w<NUL>reg` into an actual write. Base-zero integer parsing interpreted `010` as eight and rejected `08`. | Preserve tabs as separators, discard malformed control-character lines, and parse decimal or explicit `0x` hex. Wire-input tests assert that malformed lines issue no transfers. |
| Medium | Native IDF example hard-coded `REQUIRES TMP1x2`; a renamed checkout/archive changed the component's actual name and broke dependency resolution. | Derive the dependency name from the checkout. Configure regression covers both original and renamed directories; package smoke builds an isolated renamed CMake consumer. |
| Low | CMake's project version stayed at 1.0.0 after changing the manifest and running version sync. | Include CMake in generated release metadata. An isolated version-change test verifies stale detection, synchronization and recheck. Native IDF application version also comes from the manifest. |
| Low | Native IDF's prompt has no trailing newline and could remain in a buffered stdout stream. | Configure the example console as unbuffered, matching sibling examples. |
| Low | CLI could show unquantized thresholds and an unnormalized offline threshold; health omitted dirty-cause and pending-conversion details already available in the driver. | Reflect normalized settings after setup/bind/begin, and expose cached dirty cause and conversion flags without bus traffic. |
| Low | Framework-free macro-collision regression was outside the ordinary CMake/CI test path; generated nested IDF/PlatformIO artifacts could enter a release export. | Run the framework-free executable in CTest, strengthen export exclusions, and add archive inspection plus isolated consumer compilation/link/execution to CI. |
| Documentation | Integration documentation allowed callback lifetime to end at `end()`, although raw access/probe/recovery retain the binding. Comparison text overstated cooperative configuration. | Require callback/context lifetime through unbind/replacement/destruction; document synchronous transfer bounds and 36/72 ms settling waits. |

Implementation: [core organization](code-structure.md), public contract in
`include/TMP1x2/TMP1x2.h`, shared CLI in `examples/common/Tmp1x2Cli.cpp`, and
regressions in `test/test_core.cpp` and `test/cli/test_cli.cpp`.
The EM write-failure matrix also exercises all 11 transition callbacks in both
directions, with failing writes either accepted or rejected by hardware: 44 cases.

## Functional, status and health parity

| Area | Assessment |
| --- | --- |
| Core ownership | Matches the common external-owner contract: C++17, injected synchronous bounded callbacks, no platform dependency, allocation, logging, bus lifecycle or hidden retries. |
| Transport | Uses terminal `Status` callbacks like ADS1115/OPT4001 and several other sensors. Some peers use `TransportResult`, `TransportStatus` or request/result structures to carry additional evidence; these are not binary-compatible universal callback types. |
| Status | Common `{code, detail, msg}`, static diagnostic strings, `ok/is/inProgress`, explicit bool and factories. Transport detail is retained; callback IN_PROGRESS is rejected as a terminal transport violation. Error enum ordinals are library-specific. |
| Health | Passive UNINIT/READY/DEGRADED/OFFLINE, saturating counters and timestamps. Explicit tracked success restores READY. Local validation and readiness do not count as physical failures; probes/raw APIs bypass tracked health. Adapter counters include diagnostic traffic. Some peers intentionally latch OFFLINE or expose separate transport/configuration/operation state. |
| Configuration trust | Distinct from transport health. Partial writes retain desired settings and dirty cause; complete reapplication clears trust uncertainty. Observed format uncertainty now also survives failed operations. |
| Sensor coverage | All four registers, normal/extended signed temperatures, four rates, shutdown/one-shot, thresholds, comparator/interrupt ALERT, both polarities, all fault queues and optional application GPIO sampling. Explicit TMP112D address-select support at 0x40..0x43 rejects physical ALERT GPIO configuration. |
| Lifecycle | Bind/end/unbind are bus-silent; shutdown is explicit and fallible. Raw APIs and probe need a binding, managed operations need initialization, and OFFLINE does not block an explicit attempt. |
| Measurement | Failed outputs remain unchanged. One-shot start/readiness/tryRead and bounded blocking convenience exist. Continuous reads return the latest register; the device has no continuous sample counter or universal data-ready flag. |
| Cooperative operations | Bus-silent admission for initialization/configuration/recovery/shutdown/read, explicit transfer budgets, deadlines, cancellation, staged desired settings, lifetime-unique tokens and exactly-once retained results. Synchronous conveniences share the configuration engine. |
| Cross-framework CLI | Both adapters compile the same processor, preserving help sections, 32-column command layout, ANSI controls, aliases, parser and health diagnostics. |
| Field helpers and names | `init`, bound-profile `begin`, `startInit`, copied settings/samples, register-word aliases, pure validation/encoding, acquisition provenance, health snapshots and outside-change invalidation follow applicable peer conventions. |
| Shared-bus chip commands | Explicit general-call reset and receive-only SMBus Alert Response are available separately from per-device initialization/recovery. ARA retains the raw byte and uses model-specific status interpretation. |
| Builds/releases | Manifest-driven metadata, standalone CMake, native-IDF component/example, pinned managed PlatformIO, S2/S3 examples, host tests and package smoke checks. |

`wreg` is a tracked register write that invalidates managed configuration; its
help now says so. Separate raw APIs and CLI commands bypass health while still
invalidating managed configuration trust after writes. Quiet runs retain samples
and error summaries; adapter counter reset leaves driver health untouched.

## Follow-up gap closure

- Added a complete [owner-operation API](owner-operations.md), including bounded
  polls during both EM settling intervals. Independent tests cover every callback
  failure, accepted/rejected partial writes, cancellation, deadline boundaries,
  wraparound, result identity/retention and precise transport-health accounting.
- Added run statistics, quiet sampling, adapter counter reset, separate raw CLI
  commands, register conversion helpers and optional ALERT GPIO diagnostics.
- Added finite cooperative mixed stress: probe, live configuration, threshold
  and sample phases, separate check/sample statistics, and interruptible waits.
  Optional GPIO setup now rejects invalid physical pins and I2C pin collisions.
- Added explicit model/address capabilities for TMP112D address-select variants,
  including all eight supported address candidates in both adapters and discovery.
- Further lifecycle testing found that rebinding or recovery could abandon an
  unfinished manually triggered one-shot without retaining uncertainty. Both now
  return BUSY; explicit `end()` preserves evidence for subsequent recovery.
- Actual Arduino compilation caught a new internal enum collision with `LOW` and
  `HIGH`. Renamed the phases and added both macros to the framework-free header
  regression alongside Xtensa's `INTERRUPT`.
- The subsequent full-feature pass added explicit general-call reset and ARA,
  reusable field helpers and canonical peer names. A chip-by-chip/function-by-
  function [coverage matrix](feature-coverage.md) records the mapping and hardware
  limits. ARA status interpretation differs between the published TMP102 and
  TMP112 descriptions, so raw evidence is retained and decoding is model-aware.
- Scan/discovery and read-only self-check now run cooperatively. `selftest full`
  exercises 18 verified configuration profiles and restores the captured baseline,
  with explicit cancellation/restoration failure results.

## Additional datasheet and structure review

A further pass checked direct profile adoption, interrupted threshold observations,
CLI reuse and the datasheets' byte-by-byte CONFIG updates. It found and fixed:

| Priority | Reproduction | Fix and evidence |
| --- | --- | --- |
| High | Initialize normal format, change hardware EM externally while TEMP retains its previous payload, then call `setExtendedMode(true)` directly or `begin()` with the new EM. Replacing the cached profile before observing hardware discarded the previous format; the model again returned 25 C as 50 C. | Synchronous profile changes and rebinding retain the previous format's refresh requirement. Twelve regression cases cover both directions, clock/no-clock, setter/reinitialization and the already-correct staged owner path. Completed refresh returns 25 C; a missing clock leaves configuration untrusted until cooperative recovery. |
| Medium | Change TLOW externally, then fail the following THIGH read in `readThresholds()`. The call failed but the already-observed low-threshold mismatch was forgotten and typed reads remained allowed. | Compare and retain each threshold observation immediately. Sixteen cases cover both formats, either changed threshold, failures at every read and successful completion. Failed outputs remain unchanged and health records only the actual transfers. |
| Medium | Call CLI `setup()` again during an owner job, sampling run, full configuration test or pending manual conversion; or supply an invalid replacement. Platform/configuration callbacks could be replaced while previous work still owned state. | Reject active replacement, validate before changing an idle session, and clear old input/results/statistics on successful reuse. Regressions check bus-silent rejection, preserved callbacks, successful replacement and retained format evidence. |

The public header/API layout remains aligned with siblings. The implementation is
now split into lifecycle/transport, configuration, measurements and cooperative
operations; the CLI has separate dispatch, diagnostics and output files. All 87
existing core definitions remain present with unchanged signatures. Synchronous
and owner configuration still share one state machine. CMake, native IDF, SDK
checks and package validation include every source. See [code organization](code-structure.md).

The additional specification review used TMP102 SBOS397I sections 6.3–6.5 and
TMP112 SBOS473L sections 7.3–7.5, alongside the archived Q1 specifications.
Managed format transitions first finish conversion in the old format, program
the new EM separately with OS clear, then trigger and confirm a conversion.
This also handles the configuration register's byte-by-byte update behavior.
No additional writable sensor setting was found to be inaccessible. Deliberate
full-word access, transport-owned timing and specification ambiguities are recorded
in the [coverage matrix](feature-coverage.md). All 34 recorded archive hashes
passed again; vendor artifacts and licenses are unchanged.

## Hardware differences and validation limits

- The device has no readable chip ID or CRC and no per-device software reset.
  Probe means interface plausibility. Shared-bus reset requires explicit
  `busreset`/`reset all`; it is never substituted for per-device initialization.
- High-speed master-code sequencing and the autonomous serial-interface timeout
  remain application-controller/hardware behavior. Complete register access is
  available without relying on pointer persistence or partial-word transfers.
- Register reads may acknowledge interrupt ALERT. Host models cannot establish
  electrical timing, physical sensor accuracy, GPIO behavior or shared-bus
  scheduler correctness.
